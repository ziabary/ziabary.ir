# راهنمای کوتاه ویرایش محتوا

## مقاله و ترجمه

مقاله‌ها در `src/lib/content/articles/` هستند. هر مقاله `slug`، `lang`، `date` و وضعیت مستقل دارد؛ `id` اختیاری است و در نبود آن `lang:slug` به کار می‌رود. نبود ترجمه حالت عادی است. متن زبان‌های دیگر را برای برابری تعداد مقاله‌ها تولید نکنید.

برای نسخهٔ واقعاً متناظر، عضویت را در `src/lib/translation-groups.json` ثبت کنید:

```json
{
  "example-work": {
    "fa": "persian-slug",
    "en": "different-english-slug"
  }
}
```

این فقط مثال است و عضو محتوای سایت نیست. نبود `es` مشکلی ندارد. می‌توان به‌جای نگاشت مرکزی از `translationGroup` مشترک در frontmatter استفاده کرد؛ دو روش نباید متعارض باشند. بیش از یک نسخهٔ منتشرشده در هر زبان، نام عضو ناموجود و عضویت متعارض خطای ساخت هستند. `draft:true`، تاریخ آینده و `status:planned` در انتشار و رابطهٔ زبان در دسترس حذف می‌شوند. تاریخ ترجمه همان تاریخ اصلی اثر می‌ماند؛ ویرایش قالب دلیل تغییر `updated` نیست.

همین نگاشت، گروه «همین مطلب» در زبان‌گردان و hreflang را می‌سازد. مقصد «مطالب به زبان‌های دیگر» صرفاً آرشیو همان بخش است. اسکریپت sitemap حق حدس‌زدن یا بازنویسی رابطهٔ ترجمه را ندارد.

## مجموعهٔ planned

دادهٔ فارسی در `src/lib/guides.ts` و انتخاب‌های مستقل EN/ES در `src/lib/localized-guide-collections.ts` است. برای آغاز انتشار، مطالب واقعی و منتشرشده را با ترتیب دستی وارد `items` کنید و `status` را به `published` تغییر دهید. یک مجموعهٔ published بدون مطلب قابل استفاده، همچنان planned محسوب می‌شود. وضعیت هر زبان جداست. کارت، شمارنده، صفحه، noindex، sitemap و جستجو از همین وضعیت استفاده می‌کنند.

دو مجموعهٔ GPU در `docs/drafts/` استثنای قدیمی پیش‌نمایش توسعه‌اند؛ وضعیت فعلی آن‌ها در `CONTENT-REVIEW.md` توضیح داده شده است. برای انتشارشان باید manifest و ثبت مجموعهٔ همان زبان به‌طور صریح بازبینی شود؛ تغییر صرف کارت یا لینک کافی نیست.

## فهرست مقاله و لینک ماندگار

فهرست برای دست‌کم سه H2 فعال است. تنظیم اختیاری frontmatter:

```yaml
toc: auto # یا true یا false
```

تیترهای متن را طبیعی بنویسید. IDها هنگام Markdown/build ساخته می‌شوند و H3های بخش فعال زیر H2 دیده می‌شوند. برای پیوندی که باید با تغییر عنوان ثابت بماند:

```markdown
## عنوان قابل ویرایش {#stable-id}
```

ID صریح تکراری مجاز نیست. ID قدیمی منتشرشده را حذف نکنید؛ در صورت تغییر، یک alias مانند `<span id="old-id"></span>` بگذارید. در مجموعه، ID هر فصل با `chapter-id--` نام‌گذاری می‌شود و لینک‌های داخلی همان فصل هم تغییر می‌کنند؛ aliasهای قدیمی به نخستین مالک خود می‌رسند. متن فصل از همان Markdown مقاله می‌آید. نمایش بستهٔ فصل محتوا را از HTML حذف نمی‌کند.

## موضوع، قالب و پروژه

`category` قدیمی حفظ شده است. `topic`، `format` و `project` مستقل‌اند؛ نگاشت دسته‌های روشن، استثناهای بررسی‌شده و انتخاب دستی صفحه‌های موضوع در `src/lib/topics.ts` قرار دارد. ترتیب `related` و ترتیب انتخاب موضوع‌ها دستی است. سفرنامه موضوع مستقل اجباری نیست؛ `format: travelogue` و پروژه‌ای مانند `project: targoman` را با موضوع اشتباه نگیرید. برای زبان دیگر فقط با موجودی واقعی صفحهٔ موضوع بسازید.

## خلاصه، تصویر و فایل ارائه

خلاصهٔ کامل در frontmatter باقی می‌ماند؛ آرشیو سه خط و بازتاب‌ها سه خط همراه با بازکردن ادامه نشان می‌دهند. برای نوشتهٔ خود صاحب سایت، `showInMedia` و `external` دو مسیر «خواندن در سایت» و «انتشار در رسانه» را فعال می‌کنند. متن کامل گزارش دیگران را وارد نکنید.

تصویر اصلی را نگه دارید. `npm run prepare:assets` با ImageMagick نسخه‌های WebP و اندازهٔ واقعی PDFهای `static/slides/` را تولید می‌کند؛ `prepare:content` پیش از dev/build آن را اجرا می‌کند. دادهٔ تولیدشدهٔ `src/lib/generated/` را دستی ویرایش نکنید. در Svelte از `imageAttributes(src, sizes)` و اندازهٔ متناسب با layout استفاده کنید؛ Markdown به‌صورت خودکار srcset می‌گیرد. تصویر شاخص بالای مقاله lazy نمی‌شود. بزرگ‌نمایی، اصل تصویر را می‌خواند.

آیکون تازه به زیرمجموعهٔ Font Awesome نیاز دارد: پس از نصب ابزار نگهداری `fonttools` و `brotli`، `python3 scripts/subset-icons.py` را اجرا کنید. اصل فونت‌ها و مجوزها محفوظ‌اند؛ این ابزار وابستگی runtime سایت نیست.

## بررسی محلی

```bash
npm run check
npm run build
npm test
npm run verify:local
npm run preview:local
```

خروجی production در `http://127.0.0.1:4186/` است. این فرمان‌ها انتشار انجام نمی‌دهند. صفحه‌بندی و آزمون موجودی از محتوای منتشرشدهٔ جاری ساخته می‌شوند. آزمون حفظ URLهای قبلی نیز باقی است؛ حذف عمدی یک URL قدیمی به ثبت redirect و بازبینی آگاهانهٔ آن آزمون نیاز دارد.
