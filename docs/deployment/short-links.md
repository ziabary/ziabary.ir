# لینک کوتاه ziabary.ir

نمونه:

`https://ziabary.ir/?t=ggsiofrgs`

مقصد:

`https://ziabary.ir/guides/gpu-selection/#int8-or-fp8-real-gpu-support`

کد از حرف اول تک‌تک کلمات مسیر و fragment، با جداکننده‌های `/`، `-` و `#` ساخته می‌شود؛ عددهای داخل کلمه، مانند INT8، حرف جدید محسوب نمی‌شوند. بنابراین مثال بالا `ggsiofrgs` است، نه `tggiofrgs`.

## رفتار برنامه

- کپی و اشتراک‌گذاری در صفحهٔ مقاله، لینک کوتاه همان مقاله را می‌سازد. دکمه‌های هر فصل مجموعه، لینک کوتاه همان فصل را می‌سازند.
- فقط مقالات، مجموعه‌ها، فصل‌ها، جدول‌های تعاملی، اسلایدها و بخش‌های منتشرشده وارد فهرست فعال می‌شوند.
- `config/short-links.json` رزرو دائمی کدهاست. آن را حذف یا از نو تولید نکنید. اگر مطلبی حذف یا پیش‌نویس شود، کد رزروشده باقی می‌ماند ولی از فهرست عمومی حذف می‌شود.
- اگر حروف اول دو مقصد یکسان باشند، مقصد جدید پسوند عددی 2، سپس 3 و ... می‌گیرد. کد قدیمی عوض نمی‌شود؛ این موضوع برای en و es که هر دو با e آغاز می‌شوند هم ضروری است.
- کد ناشناخته به مقصد حدسی یا سایت خارجی منتقل نمی‌شود. پارامترهای تکراری t پذیرفته نمی‌شوند.
- `npm run prepare:short-links` فهرست را به‌روز می‌کند و در `npm run dev` و `npm run build` هم اجرا می‌شود. تغییر فایل رزرو باید همراه محتوا کامیت شود.
- ساخت سایت و دیپلوی وجود تمام مقصدها و شناسه‌های fragment را در صفحات indexable کنترل می‌کنند.

## آروان: تنظیم CDN جدا از آپلود سایت است

فایل [short-link-redirects.json](./short-link-redirects.json) فهرست دقیق مبدا و مقصدهاست؛ **این فایل قالب import اختصاصی API آروان نیست**. `npm run deploy` تنها فایل‌های استاتیک را آپلود می‌کند و هیچ قانون CDN ایجاد نمی‌کند.

طبق [مستندات رسمی آروان](https://docs.arvancloud.ir/fa/cdn/page-rules/redirect/)، انتقال نشانی 301 در «CDN ← قوانین صفحات» تنظیم می‌شود و اولین قانون منطبق بر درخواست اجرا می‌شود. قانون انتقال باید پیش از قانون عمومی سایت قرار گیرد.

برای اولین آزمایش، فقط این مورد را آماده کنید:

| تنظیم | مقدار |
| --- | --- |
| دامنه | `ziabary.ir` |
| مسیر | دقیقاً `/` |
| شرط query | دقیقاً یک پارامتر `t` با مقدار `ggsiofrgs` |
| اقدام | انتقال نشانی، 301 |
| مقصد | `https://ziabary.ir/guides/gpu-selection/#int8-or-fp8-real-gpu-support` |
| نگهداری query مبدا | خاموش؛ پارامتر `t` نباید به مقصد منتقل شود |

**تطبیق دقیق query باید در پنل/پلن دامنه تأیید و آزمایش شود.** مستندات عمومی بررسی‌شده انتقال URL و wildcard را توضیح می‌دهند، اما رفتار تطبیق query را به‌طور کافی مشخص نمی‌کنند. صرفاً قانون عمومی `ziabary.ir/` با انتقال ثابت نسازید: چنین قانونی ممکن است صفحهٔ اصلی همهٔ کاربران را منتقل کند. اگر پنل تطبیق query را در قوانین صفحات پشتیبانی نکند، برای حفظ قالب `?t=` باید resolver در پردازش لبه یا وب‌سرور قرار گیرد؛ افزودن متن `?t=` به الگو بدون آزمون کافی نیست.

ابتدا این چهار درخواست را بررسی کنید و سپس بقیهٔ نگاشت‌ها را فعال کنید:

```sh
curl -I 'https://ziabary.ir/?t=ggsiofrgs'
curl -I 'https://ziabary.ir/'
curl -I 'https://ziabary.ir/?utm_source=review'
curl -I 'https://ziabary.ir/?t=unknown'
```

اولی باید 301 و Location دقیقِ مقصد (همراه fragment و بدون t) داشته باشد. صفحهٔ اصلی و query نامرتبط نباید منتقل شوند. کد ناشناخته نباید به فصل نمونه منتقل شود. اگر resolver کامل روی لبه/وب‌سرور باشد، برای کد ناشناخته 404 بدهید. کش ریدایرکت باید براساس کد t تفکیک یا غیرفعال شود، نه فقط براساس مسیر `/`.

از کلید محدود به CDN همین دامنه استفاده کنید؛ کلید فضای ذخیره‌سازی S3 برای مدیریت CDN کافی نیست. هیچ کلیدی را در گیت، فایل عمومی، خروجی لاگ یا پیام قرار ندهید.

## سئو و نسخهٔ استاتیک

[گوگل ریدایرکت دائمی را سیگنال قوی برای مقصد canonical می‌داند](https://developers.google.com/search/docs/crawling-indexing/301-redirects). لینک کوتاه صفحهٔ محتوایی جدا ندارد، در sitemap قرار نمی‌گیرد و در canonical، hreflang یا دادهٔ ساختاریافته جایگزین مقصد اصلی نمی‌شود. fragment فقط برای رفتن به فصل است؛ canonical همان URL اصلی صفحه، بدون fragment می‌ماند.

تا وقتی قانون CDN فعال نشده، فایل `static/short-links.js` پس از بازکردن `/?t=...` در مرورگر، با `location.replace` به مقصد می‌رود. این **ریدایرکت HTTP 301 نیست** و بدون JavaScript کار نمی‌کند؛ canonical اولیه همان صفحهٔ اصلی است. این fallback را اثبات نصب CDN یا تضمین انتخاب canonical توسط گوگل تلقی نکنید. صفحهٔ اصلی معمولی فایل resolver را بارگیری نمی‌کند. در نسخهٔ مرورگر، کد نامعتبر یا خطای شبکه یک پیام قابل‌خواندن نمایش می‌دهد.

## آزمون محلی

```sh
npm run check
npm run build
npm test
PORT=4188 npm run preview:local
curl -I 'http://127.0.0.1:4188/?t=ggsiofrgs'
```

سرور پیش‌نمایش خروجی، 301 واقعی را شبیه‌سازی می‌کند. `npm run dev` و هاست صرفاً استاتیک، fallback مرورگر را نشان می‌دهند. آزمایش نهایی HTTP باید جداگانه روی دامنهٔ اصلی و بدون اجرای JavaScript انجام شود.
