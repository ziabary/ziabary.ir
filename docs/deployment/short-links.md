# لینک کوتاه ziabary.ir

قالب لینک‌های جدید: `https://ziabary.ir/s/ggsiofrgs/`

مقصد این نمونه: `https://ziabary.ir/guides/gpu-selection/#int8-or-fp8-real-gpu-support`

کد از حرف اول کلمات مسیر و fragment ساخته می‌شود. عددهای داخل کلمه، مانند INT8، حرف جدید محسوب نمی‌شوند. کدهای تکراری پسوند عددی می‌گیرند و کدهای قبلی هرگز به مقصد دیگری واگذار نمی‌شوند.

## ساخت و پیش‌نمایش

- `config/short-links.json` رزرو دائمی کدهاست؛ آن را حذف یا از نو تولید نکنید. فقط مقصدهای منتشرشده در فهرست فعال قرار می‌گیرند.
- `npm run prepare:short-links` نگاشت فعال را می‌سازد. `npm run build` پس از prerender، برای هر کد فعال فایل `build/s/<code>/index.html` و نسخه‌های فشردهٔ آن را می‌سازد.
- HTML هر لینک کوتاه، عنوان، توضیح و تصویر Open Graph و Twitter مقصد را دارد. به این ترتیب خزندهٔ تلگرام بدون اجرای JavaScript هم مشخصات همان مطلب را می‌خواند. تصویر مقاله همان `og:image` صفحهٔ اصلی مقاله است، نه الزاماً تصویر «پروندهٔ ویژه».
- صفحهٔ کوتاه `noindex,follow` و canonical مقصد دارد و در sitemap قرار نمی‌گیرد. مرورگر با JavaScript فوری به مقصد می‌رود؛ `meta refresh` و لینک داخل صفحه راه‌های جایگزین‌اند. fragment مقصد حفظ می‌شود.
- دکمه‌های اشتراک‌گذاری مقاله و فصل‌های راهنما از قالب `/s/<code>/` استفاده می‌کنند. مقصدهای منتشرنشده لینک کامل خود را نگه می‌دارند.
- `npm run verify:short-links` وجود مقصد، fragment، فرادادهٔ پیش‌نمایش، مسیر انتقال و حذف صفحهٔ کوتاه از sitemap را کنترل می‌کند. `npm run build` این بررسی را اجرا می‌کند.

## سازگاری لینک‌های قدیمی `/?t=`

لینک‌های قبلاً منتشرشده مثل `https://ziabary.ir/?t=ggsiofrgs` همچنان در مرورگر به مقصد می‌روند. اسکریپت انتقال پیش از CSS و برنامهٔ صفحهٔ اصلی اجرا می‌شود؛ کد ناشناخته و تکراری پذیرفته نمی‌شود. فایل `static/short-link-core.js` برای HTML کش‌شدهٔ نسخه‌های قبلی باقی می‌ماند.

این قالب قدیمی برای پیش‌نمایش تلگرام کافی نیست: هاست استاتیک برای همهٔ queryهای مسیر `/` همان HTML صفحهٔ اصلی را می‌فرستد و خزنده معمولاً انتقال JavaScript را اجرا نمی‌کند. فایل‌های `/s/<code>/` این مشکل را برای لینک‌های جدید حل می‌کنند، ولی فرادادهٔ لینک‌های `/?t=` که قبلاً در پیام‌ها آمده‌اند را عوض نمی‌کنند.

برای اصلاح پیش‌نمایش لینک‌های قدیمی، CDN یا وب‌سرور باید پیش از ارسال HTML، `/?t=<code>` را با 301 به مقصد اصلی یا صفحهٔ `/s/<code>/` منتقل کند. `docs/deployment/short-link-redirects.json` نگاشت کدها را تولید می‌کند، ولی قالب import اختصاصی API آروان نیست و `npm run deploy` هیچ قانون CDN ایجاد نمی‌کند. طبق [مستندات آروان](https://docs.arvancloud.ir/fa/cdn/page-rules/redirect/)، قوانین انتقال در CDN تنظیم می‌شوند؛ تطبیق دقیق query، اولویت قانون و کلید کش باید روی دامنه آزمایش شوند. قانون عمومی روی `/` ممکن است صفحهٔ اصلی را هم منتقل کند.

برای آزمون یک قانون قدیمی:

~~~sh
curl -I 'https://ziabary.ir/?t=ggsiofrgs'
curl -I 'https://ziabary.ir/'
curl -I 'https://ziabary.ir/?t=unknown'
~~~

فقط درخواست اول باید 301 با `Location` درست بگیرد؛ صفحهٔ اصلی باید عادی بماند و کد ناشناخته نباید به مقصد دیگری منتقل شود. دسترسی مدیریت CDN برای این مخزن فراهم نیست.

## آزمون محلی

~~~sh
npm run check
npm run build
npm test
PORT=4188 npm run preview:local
curl -s 'http://127.0.0.1:4188/s/ggsiofrgs/' | grep -E 'og:(title|image)|robots|location.replace'
~~~

سرور پیش‌نمایش به‌طور پیش‌فرض برای قالب قدیمی `/?t=` یک 301 شبیه‌سازی می‌کند. برای بررسی fallback واقعی صفحهٔ اصلی بدون قانون سرور از `LOCAL_SHORT_LINK_MODE=browser` استفاده کنید. آزمون `node tests/short-links-browser.review.mjs` رفتار همان fallback قدیمی را در مرورگر بررسی می‌کند.
