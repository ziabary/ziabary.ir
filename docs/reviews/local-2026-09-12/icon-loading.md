بررسی و اصلاح بارگذاری آیکون‌ها — ۱۲ سپتامبر ۲۰۲۶

در https://ziabary.ir/articles/ مشکل بازتولید شد: هر دو آیکون fa-table-cells و fa-list-ul در HTML هستند، اما content شبه‌عنصر آن‌ها none و عرضشان صفر است. خود SiteIcons-solid و SiteIcons-brands در مرورگر loaded هستند؛ بنابراین Font Awesome به‌طور کلی قطع نشده است.

پاسخ عمومی /fonts/icons/icons.css با وضعیت ۲۰۰ و نوع text/css دریافت شد، اما هیچ‌یک از دو تعریف آیکون جدید را نداشت. اندازهٔ CSS عمومی ۱۶۵۱ بایت و فونت solid عمومی ۱۹۰۴ بایت بود؛ نسخه‌های محلی به‌ترتیب ۱۷۲۷ و ۲۰۸۰ بایت هستند. هر دو فایل عمومی Cache-Control برابر public,max-age=3600 دارند. از این شواهد، ناهماهنگی HTML جدید با فایل‌های قدیمی آیکون تأیید می‌شود؛ این بررسی به‌تنهایی مشخص نمی‌کند نسخهٔ قدیمی از مبدأ می‌آید یا کش شبکه.

اصلاح محلی:

- prepare:icons زیرمجموعه‌های موجود و مجاز فونت را در CSS تولیدشده قرار می‌دهد.
- layout این CSS را وارد می‌کند؛ Vite آن را در فایل نسخه‌دار _app/immutable/assets/0.DvUUPNz4.css می‌سازد.
- هر سه فونت کوچک در همان CSS قرار دارند، بنابراین فایل CSS جدید نمی‌تواند به نسخهٔ کش‌شدهٔ فونت قدیمی وابسته باشد.
- بارگذاری مستقیم /fonts/icons/icons.css از app.html حذف شد. فایل‌های قدیمی برای سازگاری با صفحه‌های قبلی حفظ شده‌اند.

نتیجهٔ آزمون:

- check: صفر خطا و صفر هشدار.
- build، نقشهٔ سایت و JSON-LD: موفق.
- npm test: هر ۵۱ آزمون موفق.
- verify:local: ۱۷۳ صفحه، صفر خطا و صفر پیوند داخلی نامعتبر.
- شش حالت مرورگر: فارسی، انگلیسی و اسپانیایی؛ دسکتاپ ۱۴۴۰ روشن و موبایل ۳۹۰ تیره.
- آدرس‌های /fonts/icons/* در مرورگر عمداً مسدود بودند. هیچ درخواستی به این آدرس‌ها ثبت نشد و آیکون‌های گرید، لیست و شبکه‌های اجتماعی بارگذاری شدند. دو آیکون آرشیو content صحیح و عرض ۱۸ پیکسل دارند و دکمهٔ انتخاب فهرست کار می‌کند.
- خطای اجرای جاوااسکریپت: صفر.
