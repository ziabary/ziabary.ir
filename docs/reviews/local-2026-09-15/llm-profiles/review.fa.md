## چهار نما

| نما | ستون‌های پیش‌فرض | جزئیات و اثر فیلتر |
|---|---|---|
| شناسنامهٔ مدل | مدل، خانواده/ناشر، اندازه و معماری، ورودی/خروجی، زمینه، کاربرد اصلی، دریافت | پروندهٔ مشترک شامل معرفی، قابلیت‌ها، دریافت، راه‌اندازی، کیفیت منتشرشده و مجوز. فیلتر GGUF از فایل‌های واقعی استفاده می‌کند و ۱۱ مدل برمی‌گرداند؛ فیلتر رسمی/ثالث نیز بر ناشر فایل اعمال می‌شود. |
| راهنمای کاربرد | مدل، نقش در سامانه، کاربرد اصلی، ویژگی و دلیل بررسی، شرط استفاده، شروع کار | پیش‌فرض ۵۹ مدل با شرح اختصاصی. فیلتر RAG، بازیاب و بازرتبه‌بند و مولد پاسخ از سند را با نقش‌های متفاوت نگه می‌دارد. ماتریس اختیاری فقط ۵۰ مدل مولد/چندوجهی دارد. |
| نرم‌افزارها | نام/نسخه، نقش، سناریو، قابلیت شاخص، پلتفرم، وابستگی اجرا، شروع کار | ۱۳ نرم‌افزار؛ لینک مستقیم راهنمای رسمی و لوگوی محلی. backend و شروط قابلیت‌ها باقی مانده‌اند؛ جزئیات خالی نمایش داده نمی‌شوند. فیلتر نیاز، نقش، محیط و قابلیت همچنان بر دادهٔ نسخه‌مند اعمال می‌شود. |
| تخصصی | مدل، وظیفه، اندازه، سقف ورودی، خروجی، ویژگی، دریافت و راه‌اندازی | ۹ مدل؛ همان پروندهٔ مشترک. برای reranker خروجی امتیاز ارتباط است و ابعاد embedding به آن تحمیل نشده. نتایج منتشرشده در بخش کیفیت پرونده باقی‌اند. |

در هر ردیف مدل، پرونده، صفحهٔ رسمی، مخزن نسخه‌های دریافت و مسیر راه‌اندازی مستقیم در دسترس‌اند. انتخاب و پنهان‌کردن ستون‌ها همان کنترل سبک GPU را حفظ کرده است. فیلترها با باز/بسته‌کردن پرونده پاک نمی‌شوند؛ پارامتر پیش‌نویس، view، preset و حالت ماتریس در URL حفظ می‌شوند. لینک کپی‌شده مستقیماً همان مدل و بخش پرونده را باز می‌کند. جست‌وجو و فیلترهای دستی داخل جدول در همان جلسه حفظ می‌شوند؛ به URL لینک اشتراکی اضافه نشده‌اند.

## پوشش محتوا و فایل‌ها

| مورد | تعداد |
|---|---:|
| مدل‌های دارای معرفی اختصاصی | ۵۹ از ۵۹ |
| مدل‌های دارای راهنمای کاربرد | ۵۹ از ۵۹ |
| مدل‌های دارای صفحهٔ رسمی | ۵۹ از ۵۹ |
| مدل‌های دارای نسخهٔ دریافت تأییدشده | ۵۹ از ۵۹ |
| مدل‌های دارای مسیر راه‌اندازی مستند | ۵۹ از ۵۹ |
| مدل‌های دارای نتیجهٔ کیفیت منتشرشده | ۱۲ از ۵۹ |
| نتایج کیفیت منتشرشدهٔ موجود | ۳۷ |
| روابط مدل–کاربرد با شرح و شرط | ۶۹ |
| روابط مولد–کاربرد در صف پژوهش | ۲۵۵ |
| نسخه‌های قابل دریافت | ۱۱۱ |
| GGUF رسمی سازنده | ۴۱ |
| GGUF شخص ثالث | ۹ |
| بستهٔ Ollama با انتساب شخص ثالث | ۱ |
| مثال کد/فرمان در پنج پروندهٔ نمونه | ۶ |
| نشان محلی ناشر/مدل/نرم‌افزار، با استفادهٔ مجدد | ۲۳ |

۱۱۱ نسخه شامل ۵۰ GGUF، ۵۹ safetensors، یک PyTorch و یک بستهٔ Ollama است. هر ۱۳ گزینهٔ کوانتیزهٔ پژوهش قبلی وارد فهرست دریافت شده‌اند؛ گزینه‌های دیگری از همان مخازن رسمی و سه مدل Qwen3 Embedding نیز بررسی و اضافه شده‌اند. برای Qwen3-8B گزینه‌های Q4_K_M و Q8_0 به مخزن رسمی همان مدل وصل‌اند. تبدیل‌های GPUStack برای BGE-M3 و بستهٔ Ollama، انتشار رسمی BAAI نام‌گذاری نشده‌اند.

`ArtifactListing` با انتساب مستند به مدل دقیق، مستقل از `ModelArtifact` است. SHA مخزن فایل و اندازهٔ بایتی از فهرست واقعی فایل‌ها آمده؛ revision مدل مبنا فقط در صورت وجود ثبت شده است. ۵۹ artifact دقیق اولیه و قیود استقرار/آزمایش حفظ شده‌اند. هیچ وزن مدلی برای بازدیدکننده خودکار دریافت نمی‌شود. وزن‌های چندگیگابایتی در این کار بارگذاری یا اجرا نشده‌اند.

برای BGE-M3، متن مدل اصلی سه خروجی dense/sparse/multi-vector، بیش از ۱۰۰ زبان، ۸٬۱۹۲ توکن و ۱٬۰۲۴ بُعد را توضیح می‌دهد. مثال FlagEmbedding هر سه خروجی را درخواست می‌کند. مثال Ollama از `/api/embed` استفاده می‌کند؛ خروجی آن به تمام قابلیت‌های مدل اصلی تعمیم داده نشده است. نمونهٔ reranker امتیاز query/document می‌سازد. نمونه‌های SLM، Qwen3-8B و Coder از قالب پیام همان مخزن استفاده می‌کنند.

محتوای `ModelUseGuidance` نتیجهٔ آزمون ساختگی ندارد. شرح روابط با منبع و شرط ثبت شده و روابط تدوین‌نشده در `data/llm/v0.1.0/research/model-use-backlog.json` آمده‌اند. تعداد صف پژوهش فقط روابط معنادار بررسی‌نشدهٔ مدل‌های مولد است؛ مدل تخصصی به جدول توانایی مولد وارد نشده و محدودیت متنی شناخته‌شده به جای رابطهٔ نامعلوم شمرده نشده است.

## ظاهر و منابع تصویری

ظرفیت زمینه اکنون با عدد کامل فارسی، مثل «۸٬۱۹۲ توکن»، نمایش داده می‌شود؛ مقدار عددی اصلی برای مرتب‌سازی و فیلتر تغییر نکرده است. تصویر ورودی و معرفی، مثل GPU کنار هم قرار دارند و در موبایل یک‌ستونه می‌شوند. لوگوها محلی‌اند؛ در ردیف‌ها ۳۴×۳۴ پیکسل و در فیلترها ۲۰×۲۰ پیکسل‌اند. در مواردی مانند Gemma و Llama از نشان رسمی ناشر، Google و Meta، استفاده شده است. برای E5 نشان اختصاصی تأییدشده‌ای ثبت نشده و نشان ناشر دیگری جای آن قرار نگرفته است.

نشانی منبع هر دارایی در `data/llm/v0.1.0/research/local-brand-assets.json` ثبت شده است؛ انتساب هر نشان در همین فهرست مشخص است.

## آزمون‌ها

- `npm test`: ۱۰۵ آزمون موفق، صفر خطا؛ شامل کنترل منفی انتساب فایل، جمع اندازه‌ها و ممنوعیت outcome در راهنمای کاربرد.
- `npm run check`: صفر خطا و صفر هشدار.
- `npm run build`: موفق؛ اعتبارسنجی ۱۶۸ نشانی sitemap، ۱۷۷ بلوک JSON-LD و ۲۰۴ لینک کوتاه.
- `npm run verify:llm`: موفق؛ JSON مرجع و ماژول‌های TypeScript یکسان‌اند، منابع و هویت‌ها معتبرند.
- `npm run verify:local`: ۱۷۹ صفحه، صفر خطا و صفر مشکل fragment.
- `node tests/llm-profiles.review.mjs`: دسکتاپ ۱۶۰۰×۱۱۰۰، موبایل ۳۹۰×۸۴۴ در حالت روشن و تیره؛ ۲۳ تصویر. کنترل کپی واقعی لینک، Escape، بازگشت فوکوس، حفظ جست‌وجو/preset، لینک مستقیم پرونده، فیلتر RAG و GGUF، ۵۰ ردیف ماتریس، شرط پیش‌نویس، لوگوهای محلی و صفر خطای runtime.
- `git diff --check`: موفق.

آزمون‌ها رابط و سازگاری داده را بررسی کرده‌اند؛ اجرای inference یا سنجش کیفیت/سرعت مدل‌ها در این مرحله انجام نشده است.
