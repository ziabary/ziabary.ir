# نقشهٔ سایت

فایل `build/sitemap.xml` در پایان هر ساخت موفق، با اجرای
`scripts/generate-sitemap.mjs` تولید می‌شود. نسخهٔ دستی در `static/` قرار
ندهید؛ فهرست باید از صفحات واقعی خروجی ساخت به‌روز شود.

تولید نقشه عمداً پس از prerender و پیش از پایان ساخت انجام می‌شود، نه در
`prebuild`؛ اجرای آن پیش از ساخت ممکن است فهرست صفحات نسخهٔ قبلی را بخواند.
هر بار اجرای `npm run build` نقشه را دوباره تولید و سپس با
`scripts/verify-sitemap.mjs` اعتبارسنجی می‌کند. نبودن نقشه، XML متفاوت از
فهرست فعلی، نشانی اضافه یا حذف‌شده و نبود معرفی نقشه در `robots.txt`، ساخت
را با خطا متوقف می‌کند.

```sh
npm run check
npm run build
```

اسکریپت همهٔ صفحات `index.html` خروجی را پیدا می‌کند و نشانی کامل آن‌ها را
با دامنهٔ اصلی `https://ziabary.ir` در نقشه می‌نویسد. این فهرست شامل صفحات
فارسی، انگلیسی و اسپانیایی، مقالات منتشرشده، مجموعه‌های فنی و ارائه‌هاست.
صفحات مدیریت و صفحهٔ خطا وارد نقشه نمی‌شوند. مقالهٔ دارای `draft: true`
نیز چون صفحهٔ عمومی ندارد، در خروجی نقشه قرار نمی‌گیرد.
صفحه‌ای که در HTML خود دستور `noindex` یا `none` برای `robots` یا
`googlebot` داشته باشد نیز کنار گذاشته می‌شود.

نشانی عمومی پس از استقرار: `https://ziabary.ir/sitemap.xml`

فایل `static/robots.txt` این نشانی را معرفی می‌کند. فرایند استقرار معمول
سایت، نقشه و `robots.txt` را همراه سایر فایل‌های `build/` بارگذاری می‌کند.
تولید محلی فایل به‌تنهایی نسخهٔ آنلاین را به‌روز نمی‌کند.

`npm run deploy` ابتدا ساخت کامل را اجرا می‌کند. حتی اجرای مستقیم اسکریپت
استقرار نیز پیش از هر ارتباط با فضای ذخیره‌سازی، نقشهٔ خروجی را اعتبارسنجی
می‌کند. این بررسی انطباق نقشه با پوشهٔ `build/` را تضمین می‌کند؛ برای اعمال
تغییرات جدید محتوا، همچنان باید ساخت تازه انجام شود.

در CI نیز آزمون‌های نقشه و ساخت کامل پیش از ذخیرهٔ خروجی اجرا می‌شوند.
برای بررسی مستقل خروجی موجود از `npm run verify:sitemap` و برای آزمون
رفتار تولید و اعتبارسنجی از `npm run test:sitemap` استفاده کنید.

اگر ساخت به‌دلیل لینک شکسته متوقف شود، نقشهٔ تازه نیز تولید نمی‌شود؛ ابتدا
لینک را اصلاح کنید. برای رفع این خطا، وضعیت پیش‌نویس مقالات را تغییر ندهید
و خطاهای prerender را نادیده نگیرید.
