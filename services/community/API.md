# API v1

پاسخ‌ها JSON و `Cache-Control: no-store` دارند. خطا شکل `{ "error": "code", "requestId": "…" }` دارد. زمان‌ها epoch milliseconds هستند؛ کلید `post` مسیر canonical با slash پایانی است. دامنه، query و hash بخشی از کلید نیستند.

صفحه‌ها در نخستین درخواست از HTML عمومی سایت شناسایی می‌شوند؛ فایل sitemap، فهرست محلی و restart پس از انتشار لازم نیست. مبدأ واکشی `SITE_URL` یا اولین `SITE_ORIGINS` است. عنوان و وضعیت انتشار تا یک دقیقه cache می‌شوند؛ صفحهٔ حذف‌شده، `noindex` و یادداشت دائماً خصوصی پذیرفته نمی‌شوند. ثبت نظر علاوه بر مسیر مقاله، به نشان `data-community-slot` با `data-post` متناظر در HTML نیاز دارد. سابقهٔ صفحهٔ خارج‌شده از انتشار در پنل حفظ می‌شود.

| روش و مسیر | کارکرد |
|---|---|
| `GET /live` | زنده‌بودن پردازه |
| `GET /health` | آمادگی و public sitekey؛ در نبود پیکربندی کپچا 503 |
| `GET /api/public/stats?post=…` | شمارندهٔ هر صفحهٔ عمومی در fa/en/es؛ `views,visitors,observedVisitors,historicalVisitors`؛ بدون نظر و اطلاعات شخصی |
| `GET /api/public/comments?post=…&cursor=…` | پنج رشتهٔ تأییدشده با فرزندان؛ `comments,total,nextCursor,views,visitors` |
| `POST /api/public/comments` | `post,parent,author,body,captchaToken,requestId,website`؛ موفقیت 202 و `status: pending` |
| `POST /api/public/visit-ticket` | بدنه `{post}`؛ بلیت امضاشدهٔ دو‌دقیقه‌ای |
| `POST /api/public/visits` | `post,fingerprint,ticket,language,timezone,screen,referrer`؛ پاسخ `{counted}` |
| `POST /api/admin/login` | `username,password`؛ کوکی نشست و `{csrf,username}` |
| `GET /api/admin/session` | بازیابی اطلاعات نشست و CSRF پس از reload |
| `POST /api/admin/logout` | لغو نشست |
| `GET /api/admin/comments?status=…&post=…&cursor=…` | `threads,nextCursor`؛ حداکثر ۱۰ گفتگوی کامل به ترتیب آخرین تغییر |
| `POST /api/admin/comments/:id/moderate` | `{status}` از approved/rejected/spam/deleted |
| `POST /api/admin/comments/:id/reply` | `{body}`؛ انتشار صریح پاسخ مدیر |
| `POST /api/admin/comments/:id/block` | `{reason,days}`؛ محدودیت شبکه بین ۱ و ۹۰ روز |
| `GET /api/admin/blocks` | محدودیت‌های فعال |
| `POST /api/admin/unblock` | `{ipHash}` |
| `GET /api/admin/stats?days=30&post=…` | آمار تجمیعی روزانه، بازه، کل و هر صفحه؛ بازه به `ANALYTICS_RETENTION_DAYS` محدود می‌شود |
| `GET /api/admin/visits?post=…&cursor=…` | ۴۰ ریز بازدید با IP رمزگشایی‌شده؛ دسترسی audit می‌شود |
| `GET /api/admin/audit` | صد رویداد مدیریتی اخیر |

POST عمومی به `Origin` دقیق یکی از `SITE_ORIGINS`، JSON و بدنهٔ حداکثر ۱۶ KiB نیاز دارد. POST ادمین به Origin خود سرویس، کوکی نشست و هدر `X-CSRF-Token` نیاز دارد؛ login به CSRF نشست نیاز ندارد و با Origin/JSON/محدودیت تلاش محافظت می‌شود. API ادمین CORS عمومی ندارد. کوکی ادمین به سایت استاتیک فرستاده نمی‌شود.

نظر: نام ۲ تا ۸۰ نویسه، متن ۳ تا ۵۰۰۰، parent عدد صحیح در همان نوشته و در رشتهٔ منتشرشده؛ requestId تصادفی ۱۶ تا ۸۰ نویسه و ثابت در retry همان ارسال است. `website` باید خالی باشد. فیلد اضافی رد می‌شود. درخواست تکراری با همان id و payload ذخیرهٔ جدید ایجاد نمی‌کند.

در صف ادمین، `status` روی اعضای گفتگو اعمال می‌شود: وجود یک نظر با وضعیت انتخاب‌شده، کل رشته را با تمام وضعیت‌ها برمی‌گرداند؛ `all` همهٔ گفتگوها را انتخاب می‌کند و مقدار پیش‌فرض `pending` است. هر عضو `threads` شامل `id,post,title,updated,count,comments` است. ترتیب گفتگوها بر اساس بیشترین `updated` اعضا و سپس شناسهٔ ریشه، نزولی است؛ نظرها درون هر گفتگو به ترتیب درختی می‌آیند. `nextCursor` را بدون تغییر به درخواست بعدی بدهید؛ برای تغییر فیلتر یا مشاهدهٔ فعالیت‌های تازه از ابتدا بارگذاری کنید. صفحه‌بندی، گفتگو را به چند صفحه تقسیم نمی‌کند.

fingerprint رشتهٔ hex با طول ۶۴ است. بلیت بازدید به صفحه، IP و زمان وابسته و یک‌بارمصرف است؛ فاصلهٔ صدور تا ارسال باید ۱٫۵ تا ۱۲۰ ثانیه باشد. تغییر fingerprint در یک بلیت، بازدید دوباره ایجاد نمی‌کند. شمارش دوباره در پنجرهٔ نیم‌ساعته رد می‌شود.

بازدیدهای پیشین با ابزار `tools/import-views.mjs` وارد می‌شوند. فیلد `views` در پاسخ عمومی و آمار کل، مجموع بازدیدهای پیشین و بازدیدهای سرویس است؛ `historicalViews` در `lifetime` و هر عضو `posts` سهم آمار واردشده را نشان می‌دهد. آمار بازه، روند روزانه، بازدیدکننده و جزئیات مرورگر فقط از بازدیدهای ثبت‌شده توسط سرویس محاسبه می‌شوند.

ستون `Usuarios activos` فایل نیز با همان ضریب وارد می‌شود. `visitors` در پاسخ عمومی و هر عضو `posts` برآورد مجموع بازدیدکنندگان پیشین و شناسه‌های مشاهده‌شدهٔ همان نوشته است؛ `historicalVisitors` سهم پیشین را مشخص می‌کند و پاسخ عمومی `observedVisitors` را نیز دارد. مقادیر مسیرهای با اسلش و بدون اسلش برای برآورد هر نوشته جمع می‌شوند؛ فایل امکان حذف افراد مشترک میان این مسیرها، دوره‌های تاریخی و داده‌های سرویس را نمی‌دهد. `lifetime.visitors` تعداد شناسه‌های ثبت‌شده توسط سرویس باقی می‌ماند؛ برآوردهای تاریخی نوشته‌های مختلف به‌عنوان تعداد افراد یکتای سایت جمع نمی‌شوند. اجرای دوبارهٔ واردسازی قبلی، فقط ستون جاافتادهٔ بازدیدکنندگان را تکمیل می‌کند و شمارندهٔ بازدید را تغییر نمی‌دهد.

آمار پنل از خلاصه‌های روزانه خوانده می‌شود و جدول ریزبازدیدها را پیمایش نمی‌کند. خلاصهٔ روز جاری در همان تراکنش ثبت بازدید به‌روز می‌شود. `days` تعداد روزهای تقویمی تهران با احتساب امروز است؛ `firstDay,lastDay` مرز بازه را مشخص می‌کنند و روزهای بدون بازدید مقدار صفر دارند. تعداد بازدیدکنندگان یکتا و IPهای متفاوت بازه از آخرین روز مشاهدهٔ شناسه‌ها محاسبه می‌شود، نه جمع تعداد روزانه. `retentionDays` مدت نگهداری خلاصه‌هاست (پیش‌فرض ۱۰۹۵ روز) و `detailsRetentionDays` مدت نگهداری ریزبازدیدها (پیش‌فرض ۹۰ روز).

مهاجرت اولیه، داده‌های موجود را یک‌بار تجمیع می‌کند. اگر جزئیات یک روز پیش‌تر حذف شده باشد، مجموع بازدید آن روز حفظ می‌شود؛ تعداد یکتاهای غیرقابل‌بازیابی `null` است و `breakdownsComplete:false` جزئیات ناقص آن بازه را مشخص می‌کند. پاک‌سازی خلاصه‌های منقضی و شناسه‌های شمارش روزانه، روزی یک‌بار در چرخهٔ نگهداری ساعتی و هنگام راه‌اندازی انجام می‌شود. نیازی به cron خارجی نیست.

کدهای متداول: 400 ورودی/کپچا/parent نامعتبر، 401 نشست یا ورود نامعتبر، 403 origin/CSRF/محدودیت شبکه، 404 صفحهٔ ناموجود یا خارج از انتشار، 409 idempotency متعارض، 413 بدنهٔ بزرگ، 415 قالب غیر JSON، 429 محدودیت تعداد با `Retry-After`، 503 سرویس آماده نیست/صف پر/ظرفیت اعتبارسنجی پر؛ page_verification_unavailable یعنی واکشی صفحه موقتاً در دسترس نیست. خطاهای داخلی جزئیات، SQL، IP یا secret را به کاربر برنمی‌گردانند.

کپچا با ARCaptcha و درخواست JSON شامل `site_key`، `secret_key` و `challenge_id` در سرور اعتبارسنجی می‌شود. نام کاربری، رمز و هر دو کلید از فایل خصوصی `bootstrap.txt` خوانده می‌شوند؛ پاسخ `/health` فقط کلید عمومی را برمی‌گرداند.
