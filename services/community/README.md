# سرویس نظر و آمار بازدید

این پوشه یک سرویس مستقل است: API، پنل ادمین، رابط نظر، بارگذار مرورگر، ذخیره‌سازی، ابزارهای مدیریت و کانتینر در همین‌جا قرار دارند. سایت SvelteKit همچنان با `adapter-static` در `build/` ساخته می‌شود و برای پاسخ‌دادن به درخواست صفحه به این سرویس نیاز ندارد.

## راه‌اندازی

Node.js 24 و Docker Compose لازم است. سرویس هیچ وابستگی npm در زمان اجرا ندارد. ابتدا در ریشهٔ مخزن `npm run build` را اجرا کنید؛ سپس:

```sh
cd services/community
npm run setup
npm run catalogue
cp .env.example .env
```

ابزار setup فایل‌های `config/secrets.json` و `config/bootstrap.txt` را با دسترسی `0600` ایجاد می‌کند. رمز تولیدشده را در مدیر رمز نگه دارید و `totpSecret` یا نشانی `otpauth` را به برنامهٔ تأیید دومرحله‌ای اضافه کنید. پس از آن، `bootstrap.txt` را حذف کنید. هیچ رمز پیش‌فرضی وجود ندارد و اطلاعات ورود در خروجی فرمان چاپ نمی‌شوند.

در Cloudflare Turnstile یک widget برای دامنه‌های سایت ایجاد کنید. کلید عمومی را در `TURNSTILE_SITE_KEY` داخل `.env` و کلید خصوصی را در `turnstileSecret` داخل `config/secrets.json` قرار دهید. کلیدهای آزمایشی در حالت production پذیرفته نمی‌شوند. اعتبارسنجی هر نظر در سرور انجام می‌شود و hostname و action=`comment` نیز کنترل می‌شوند. [راهنمای رسمی اعتبارسنجی](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)

`PUBLIC_URL` نشانی خود سرویس و `SITE_ORIGINS` مبدأهای مجاز سایت است؛ نمونه برای `https://api.ziabary.ir` آماده شده است. دامنه و TLS را روی سرور تنظیم کنید؛ `Caddyfile.example` نمونهٔ پراکسی روی همان میزبان است. پورت سرویس فقط روی loopback میزبان منتشر می‌شود:

```sh
docker compose up -d --build
docker compose ps
curl --fail https://api.ziabary.ir/health
```

پنل مستقل در `https://api.ziabary.ir/admin/` باز می‌شود. ورود به رمز و TOTP نیاز دارد. پنل شامل صف بررسی، انتشار/رد/حذف/هرزنامه، پاسخ مدیر، محدودیت شبکه، آمار کل، آمار هر صفحه، روند روزانه، مرورگر و سیستم‌عامل، مبدأ ورود و ریز بازدیدها همراه IP است.

برای دریافت IP واقعی، `TRUSTED_PROXY_CIDRS` را فقط به نشانی یا شبکهٔ پراکسی‌ای محدود کنید که کانتینر واقعاً به‌عنوان peer می‌بیند؛ در شبکهٔ bridge داکر ممکن است این نشانی با loopback میزبان متفاوت باشد. مقدار پیش‌فرض خالی است و هدرهای forwarded را نادیده می‌گیرد. پراکسی باید `X-Forwarded-For` ورودی کاربر را جایگزین کند؛ پیکربندی نمونه همین کار را می‌کند. endpointها به `X-Forwarded-Proto` ارسالی کاربر اعتماد نمی‌کنند.

## اتصال سایت

اتصال سایت پیش‌فرض برای `https://api.ziabary.ir` آماده است. برای تغییر نشانی می‌توانید در فایل `.env.local` **ریشهٔ سایت** قرار دهید:

```dotenv
PUBLIC_COMMUNITY_API_URL=https://api.ziabary.ir
```

سپس سایت را با `npm run build` و فرمان معمول استقرار منتشر کنید. این متغیر عمومی است و رمز یا کلید خصوصی در آن قرار نمی‌گیرد. برای خاموش‌کردن کامل اتصال، مقدار متغیر را صریحاً خالی بگذارید؛ در این حالت سایت هیچ درخواستی برای سرویس نمی‌فرستد. تا زمان آماده‌شدن سرویس، بخش نظر پنهان است و پس از اتصال خودش نمایان می‌شود.

کد اتصال سایت فقط یک import در layout و یک محل خالی برای نظر در صفحهٔ نوشته دارد. همهٔ کد سرویس و UI داخل این پوشه است. کلید صفحه مسیر canonical همان نسخهٔ زبانی است؛ آمار و نظر نسخه‌های فارسی، انگلیسی و اسپانیایی مستقل‌اند.

## قطع و وصل، سرعت بارگذاری

- محل نظر در HTML اولیه `hidden` است و فضا اشغال نمی‌کند.
- آغاز کار بعد از رویداد `load` و زمان بیکاری مرورگر است؛ اسکریپت سرویس، CSS و fingerprint پیش از آن بارگیری یا محاسبه نمی‌شوند.
- بررسی سلامت timeout برابر ۱٫۸ ثانیه دارد. در دسترس بودن سرویس در مسیر رندر یا build سایت قرار ندارد.
- اگر سرویس در دسترس نباشد، فرم و نظرها پنهان می‌مانند. خطای شبکه یا 5xx پس از نمایش هم بخش را پنهان می‌کند؛ متن فرم در حافظهٔ همان صفحه حفظ می‌شود.
- بررسی دوره‌ای هنگام اتصال هر ۶۰ ثانیه است. پس از خطا، فاصلهٔ تلاش از ۳۰ ثانیه تا ۵ دقیقه افزایش می‌یابد. رویدادهای `online` و بازگشت به تب، بررسی زودهنگام را فعال می‌کنند. در تب پنهان polling شبکه انجام نمی‌شود. رخداد `offline` بخش را بلافاصله پنهان می‌کند.
- پس از اتصال دوباره، نظرها تازه و فرم نمایان می‌شود. بررسی‌های قبلی هم‌زمان تکرار نمی‌شوند و هنگام ترک صفحه لغو می‌شوند.
- کپچا فقط هنگام تمرکز روی فرم یا انتخاب پاسخ بارگیری می‌شود. برای خواندن صفحه یا دیدن نظرهای منتشرشده بارگیری کپچا لازم نیست.

## شمارش بازدید و نگهداری داده

فهرست صفحه‌های مجاز از sitemap ساخته‌شده استخراج می‌شود. صفحهٔ noindex، پیش‌نویس و یادداشت دائماً خصوصی `kazan-investment-reality` وارد فهرست نمی‌شوند. پاسخ‌دهی به نظر فقط برای نوشته‌های این فهرست فعال است؛ آمار سایر صفحه‌های عمومی نیز ثبت می‌شود.

اثر انگشت شامل مشخصات کلی مرورگر، زبان، ابعاد گرد‌شدهٔ نمایشگر، منطقهٔ زمانی و یک شناسهٔ تصادفی first-party است. canvas، صدا، فهرست فونت‌ها و اثرانگشت‌گیری پنهان استفاده نمی‌شوند. خروجی SHA-256 به سرور می‌رود و آنجا با کلید خصوصی HMAC می‌شود. IP همراه هر بازدید با AES-256-GCM رمز می‌شود. فقط پنل احرازهویت‌شده ریز IP را باز می‌کند و مشاهدهٔ جزئیات را در audit ثبت می‌کند. متن نظر عمومی هیچ IP یا شناسهٔ مرورگری ندارد.

یک مرورگر در هر صفحه و هر بازهٔ نیم‌ساعته یک بازدید ایجاد می‌کند. برای ثبت، بلیت امضاشده و یک‌بارمصرف، حداقل ۱٫۵ ثانیه فاصله و دیده‌شدن صفحه لازم است. ربات‌های شناخته‌شده با user-agent کنار گذاشته می‌شوند. fingerprint و IP قابل تغییرند؛ به همین دلیل رابط از عنوان «بازدیدکنندهٔ تقریبی» استفاده می‌کند. پاک‌کردن storage یا تغییر تنظیمات مرورگر می‌تواند شناسه را عوض کند.

ریز بازدیدها و IP نظرها پیش‌فرض ۹۰ روز نگه‌داری می‌شوند؛ `VISIT_RETENTION_DAYS` آن را تنظیم می‌کند. پاک‌سازی در آغاز و سپس ساعتی انجام می‌شود. شمارندهٔ کل، آمار روزانهٔ تجمیعی و شناسه‌های HMAC برای آمار کلی باقی می‌مانند. مبدأ ورود فقط origin است؛ query و مسیر خصوصی referrer ذخیره نمی‌شود. ساعت نمایش گزارش و روزبندی آمار تهران است.

## بررسی نظر و کنترل سوءاستفاده

همهٔ نظرها و پاسخ‌های خوانندگان `pending` می‌شوند. فقط ادمین می‌تواند منتشر کند؛ پاسخ خود ادمین با دکمهٔ صریح «ثبت و انتشار پاسخ» منتشر می‌شود. رد یا حذف والد، کل زیررشته را از نمایش عمومی خارج می‌کند. عمق پاسخ چهار سطح و سقف هر رشته ۱۰۱ نظر شامل والد است. صفحه‌بندی پنج رشته را با پاسخ‌هایشان می‌گیرد.

کنترل‌ها شامل کپچای یک‌بارمصرف، honeypot، محدودیت اندازه و نوع JSON، اعتبارسنجی فهرست فیلدها، SQL پارامتری، نمایش متن با `textContent`، کنترل parent و صفحه، کنترل دوبارهٔ والد پس از کپچا، شناسهٔ idempotency، صف محدود، CORS محدود به originهای تعیین‌شده و rate limit پایدار در SQLite هستند. سقف پیش‌فرض نظر پنج درخواست در ثانیه برای کل سرویس است (`COMMENTS_PER_SECOND`). هر IP نیز سقف‌های دقیقه‌ای، سه تلاش جدی در ده دقیقه و بیست تلاش در روز دارد؛ تلاش ناموفق کپچا هم از سهمیه مصرف می‌کند. محدودیت‌ها با restart صفر نمی‌شوند.

ورود ادمین از scrypt، TOTP با جلوگیری از replay، محدودیت تلاش ورود، کوکی HttpOnly/Secure/SameSite=Strict، نشست هشت‌ساعته با انقضای بیکاری سی‌دقیقه‌ای، CSRF، کنترل Origin و Fetch Metadata استفاده می‌کند. CSP پنل اجرای اسکریپت خارجی و جاسازی در iframe را می‌بندد. اقدامات مدیریتی audit می‌شوند. [مرجع احراز هویت OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)، [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238)

کانتینر با کاربر غیر root، فایل‌سیستم read-only، حذف capabilityها، محدودیت CPU/حافظه/تعداد پردازه و volume جدا اجرا می‌شود. SQLite در WAL و تراکنش‌های کوتاه استفاده می‌شود؛ این نسخه برای **یک replica** طراحی شده است. فایل پایگاه داده روی دیسک محلی میزبان باشد؛ آن را بین چند replica یا روی NFS به اشتراک نگذارید. rate limit برنامه جای کنترل ترافیک حجیم در پراکسی/CDN را نمی‌گیرد.

سقف فایل اصلی پایگاه داده پیش‌فرض ۵۱۲ MiB است (`MAX_DATABASE_MIB`) تا ترافیک جعلی نتواند بدون سقف آن را بزرگ کند. فایل موقت WAL و پشتیبان‌ها را نیز در پایش فضای volume حساب کنید. در رسیدن به سقف، نوشتن داده خطا می‌دهد و سایت بخش نظر را پنهان می‌کند؛ پاک‌سازی دوره‌ای یا افزایش آگاهانهٔ سقف و restart، امکان نوشتن را برمی‌گرداند. ورود ناموفق و خروج مدیر هم ثبت می‌شوند و اعتبارسنجی هم‌زمان رمز محدود است.

## پشتیبان، به‌روزرسانی و بازیابی

```sh
# snapshot معتبر حتی با WAL فعال؛ فایل را سپس از میزبان خارج کنید.
docker compose exec -T community node tools/backup.mjs /data/community.sqlite /data/backups/community.sqlite
docker compose cp community:/data/backups/community.sqlite ./backups/community.sqlite
```

ابزار از overwrite پشتیبان موجود جلوگیری می‌کند؛ برای نوبت بعد نام تازه انتخاب کنید. فایل پشتیبان، `config/secrets.json` و تنظیمات دامنه را جداگانه و امن نگه دارید. کلید رمز IP و کلید HMAC باید هنگام بازیابی حفظ شوند. برای restore سرویس را متوقف کنید، snapshot را در volume خالی به نام `community.sqlite` با مالکیت uid=1000 و دسترسی 0600 قرار دهید و همان secrets را برگردانید. WAL/SHM قدیمی را از snapshot دیگری همراه آن نگذارید. سپس سرویس را روشن و `/health`، ورود ادمین، آمار و یک نظر عمومی را کنترل کنید.

برای تغییر رمز/عامل دوم، روی میزبان `node tools/setup.mjs --rotate-admin` اجرا و سرویس را restart کنید. این فرمان کلیدهای رمزگذاری و آمار را حفظ می‌کند و نشست‌های قبلی در آغاز سرویس باطل می‌شوند.

با هر انتشار محتوای سایت، پس از build دوباره `npm run catalogue` و `docker compose restart community` را اجرا کنید. صفحه‌های خارج‌شده از فهرست، برای API عمومی غیرفعال می‌شوند و سابقه‌شان در پنل باقی می‌ماند. با تغییر کد سرویس از `docker compose up -d --build` استفاده کنید. پایهٔ Docker با digest ثابت شده؛ برای دریافت اصلاحات Node و سیستم‌عامل، نسخه/digest را آگاهانه به‌روزرسانی و تست کنید.

## تست و API

```sh
npm test
docker build -t ziabary-community:local .
```

تست‌ها احراز هویت، کپچا، moderation، پاسخ‌ها، race والد، XSS به‌صورت متن، rate limit، IP پراکسی، شمارش/تکرار بازدید، حفظ آمار تجمیعی، backup و قطع‌و‌وصل بدون درخواست پیش از load را پوشش می‌دهند. `test/browser.review.mjs` بررسی مرورگر روی build واقعی سایت است؛ توضیحات اجرای آن در همان فایل آمده است.

API در [API.md](./API.md) مستند شده است. هیچ endpoint ثبت‌نام عمومی ادمین، انتشار مستقیم نظر کاربر، بارگذاری فایل یا ایمیل وجود ندارد. برای دسترسی اپراتوری از تنظیمات secret روی میزبان استفاده می‌شود.
